# GS48 differential-test findings

The two where-clause fixtures failed with the same Conversion diagnostics in the sweep recorded in `docs/burndown.md`, despite earlier passing reports. The failure is not specific to where clauses: a generic procedure called with `[3]int` followed by `[4]int` reused the first array-length expression's checked row while constructing the second signature. Instance cache keys already distinguish constant arguments. `expression_new_instance` now selects the new instance's typed view before constructing its signature, just as it already did before checking its body. `generic_array_instances` covers both call orders, repeated instances, and independent length parameters.

The `type_info_of` fixture previously assumed an unknown typeid returned nil. Official `base/runtime/core.odin:814–825` returns `type_table[0]` for an unmatched typeid. Ginger Bill's `lb_setup_type_info_data_giant_array` in `refs/Odin-upstream/src/llvm_backend_type.cpp:272–279` explicitly creates a zero-initialized Type_Info global for slot zero. Our table previously left that slot nil. It now references a zeroed descriptor. The fixture checks that invalid and zero typeids return the same nonnil descriptor with zero id, size, and alignment. This follows the runtime and compiler source contract rather than preserving the fixture's old checksum.

The `demo_section_bit_set_type` failure was already recorded in the burndown sweep. The runtime `card` signature is `proc(s: $S/bit_set[$E; $U]) -> int`. The polymorphic matcher supported arrays and maps but not bit sets, so it attempted to resolve unbound E as an ordinary type. Bit-set patterns now bind the element and storage types using the existing Poly_Bindings representation. The effective storage type is calculated in the same way as our existing `type_bit_set_underlying_type` implementation. Official matching is in `refs/Odin-upstream/src/check_type.cpp`, `subst_unify`, Type_BitSet case; the runtime cardinality procedure supplies the concrete use.

The `raw_data` fixture was invalid before GS48. Official `check_builtin.cpp`, BuiltinProc_raw_data, accepts a typed string, slice, dynamic array, or pointer to array, not an untyped string literal. The write marker is now a typed string. Official also rejects `cast([]u8)string`; the fixture now uses `transmute([]u8)string`, preserving the same backing pointer that this test inspects. Differential testing passes with checksum 127 and the same single-byte output.

`cstring_literals` remains an official-compiler limitation, not an invalid fixture. Once its main convention was corrected, official checking accepted it but LLVM emission asserted that `cstring_to_string` was missing. Official `check_expr.cpp` explicitly handles cstring comparisons, and `llvm_backend_expr.cpp:2535–2542` emits the cstring-to-string runtime conversion. The original reproducer is preserved. Replacing comparisons with explicit `string(...)` conversions is not used to conceal the assertion.

`user_collections/app` is a runner-configuration limitation already recorded in the burndown sweep. It requires the `nabla` and `other` collections, which its dedicated driver test supplies. The differential runner supplies neither. The empty `user_collections` container is not itself a package. Its valid imports are unchanged.
